## Ranked refactoring proposal (not done: each is a real split, wanted only with time to test)

1. **office.gd (1231 lines, 83 functions): split the camera staging and the pointer picking out.**
   It holds the scene build, floor loading, interactables, panel opening (look, whiteboard, trafohuisje,
   KPI board, explainers), talk framing and camera shots (`frame_talk`, `stage_talk`, `follow_walking_talk`,
   `frame_face`, `frame_scene`, `_two_shot`, `talk_yaw`, `talk_point`, `frame`, `frame_point`), and mouse
   picking (`hover_*`, `click_*`, `_collision_faces`). Proposal: `OfficeStaging` (camera framing for talks
   and scenes, ~200 lines) and `OfficePointer` (hover/click resolution, ~100 lines), both holding a
   reference to the Office like OfficeTells/OfficeReactions already do. Risk: medium; every office test
   (office_scene, office_people, third_person, talk_view walking mode) and play_shot states touch it.
   Biggest gain: talk staging is where slice-3 work will land next.
2. **session.gd (1435 lines): move the "In passing" and talk plumbing (lines 934-1435) into a
   `SessionTalks` helper.** GameSession mixes the game's actions and views with ~500 lines of greetings,
   chatter, check-in prompts, dialog start/move/end and expert-talk routing. The public API on GameSession
   can stay as one-line forwards so callers do not change. Risk: medium (save keys `passing`, many UI
   callers); low if the forwards stay.
3. **missions.gd (1135 lines): extract the coach (`ask_coach`, `_question`, `_say`, `_conditions`,
   `fading_fix`, `stage_of`, ~100 lines) into `Coach`**, and the per-day sync passes (`_sync_checkins`,
   `_sync_repairs`, `_reopen_faded`, `_reoffer_recurring`, `_switch_on_forks`, `_retire_orphans`) into
   one `MissionSync`. The coach is the piece slice 3 changes most (number questions, Kata). Risk: low
   for the coach (pure, tested in test_missions, test_session and test_coach_numbers), medium for the sync passes (order matters).
4. **region.gd (1077 lines): extract Sustain + Stagnation drift (lines 904-1077) into `RegionSustain`.**
   The file is already sectioned by PDCA phase, which reads well; only sustain/decay is a separate
   concern with its own state. Risk: low-medium (save state, test_sustain*).
5. **people.gd (890) / dialog.gd (862):** cohesive; leave.
6. **Number formatting lives in three places:** `UiText.money`/`UiText.decimal` (ui), `ExplainerRig.nl`
   (thousands dot + decimal comma), `CoachNumbers` (rules) repeats the decimal comma. A small `NlNumber`
   in `content/` or `rules/` that both layers may use would hold one rule. Risk: low; check every
   formatted string in tests.
7. **The remaining Godot-built props** (`office_desk._box`, `office_placeholder._box`, `van_ride_town._box`)
   differ (own material, collision body, return value) and stay; fold them into `OfficeMesh` only when
   one of them is touched anyway.
